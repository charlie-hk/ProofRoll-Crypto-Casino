Provably fair, in plain terms

  1. Commit. Before any bet, the house publishes keccak256(serverSeed). The seed itself stays hidden, but it is now locked.
  2. Your seed. You choose a client seed. The house can't know outcomes without it, and you can't without the server seed.
  3. Play. Each bet gets a nonce. The result is a pure function of (serverSeed, clientSeed, nonce) — nothing else.
  4. Reveal. The server seed is revealed. You check it matches the earlier commit, then replay every result yourself on the Verify tab.

This page runs that exact engine in your browser. In production the same logic lives in the Solidity contracts, settlement is driven by the operator, and funds sit in a bankroll with per-bet exposure locks and a timeout refund. Source and tests are on GitHub.
